# Portfolio Redesign — Design Spec

Date: 2026-10-14
Branch: `redesign`

## Goal

Rebuild the look and motion of the single-page portfolio while keeping the
same stack: static HTML/CSS/JS, no build step, PHP guard + EmailJS for the
contact form, FTP deploy via GitHub Actions.

Visual reference: Dribbble "Personal Portfolio Landingpage" (Syahru Murtadho /
Hypocreate) — light grey monochrome, heavy uppercase grotesk name, black-and-white
cut-out portrait, sparkle, round "Schedule Call" badge with hand-drawn arrow,
client avatars, logo strip, dated experience list.

Motion reference: markovcorneliuskelvin.netlify.app (linked from the Threads
post; the video itself could not be viewed) — sketch portrait that reveals the
colour photo around the cursor, 3D ring of project cards orbiting the portrait,
masked text reveals, counting stats.

## Decisions (from Q&A)

| Topic | Decision |
|---|---|
| Animations | Sketch→photo hover reveal; 3D project-card ring; text reveal + counters. No cursor-following row preview. |
| Theme | Light by default, dark-mode toggle kept |
| Accent | Lime `#D4FF3A` on grey/black monochrome |
| Motion library | GSAP + ScrollTrigger from `cdn.jsdelivr.net`, exact pinned version |
| Language | English |
| Portrait | User supplies new photo, ≥1200px tall; cut-out via remove.bg |
| Sketch technique | Approach A: pre-rendered `portrait-sketch.png` + CSS mask on colour photo |
| Mobile | Touch-drag moves the reveal circle; ring auto-rotates |
| "Schedule Call" badge | Links to WhatsApp (`https://wa.me/<number>`) |
| Testimonials / logos | Both, real content supplied by user. Nothing invented. |
| Sections | Education + Languages merged; Skills as compact category grid; project modal kept |

## Visual system

- Colours as tokens in `:root`:
  - light: bg `#E6E4E0`, surface `#F2F1EE`, text `#111111`, muted `#6B6B6B`, accent `#D4FF3A`
  - dark: bg `#0E0E0E`, surface `#1A1A1A`, text `#F2F1EE`, muted `#8A8A8A`, accent `#D4FF3A`
  - The accent is a fill only. It never colours text on the light background (contrast); text on accent is `#111`.
- Type: Archivo Black for the display name and headings, Inter for body. Both from Google Fonts.
- Recurring motifs: sparkle ✦, black square logo block, black "Contact Me ↗" button, rotating round badge.

## Behaviour

### Sketch → photo reveal (`hero.js`)

- Markup: `.portrait` holds `img.portrait-sketch` and `img.portrait-photo`, stacked.
- `.portrait-photo` uses `mask-image: radial-gradient(circle var(--r) at var(--mx) var(--my), #000 60%, transparent 100%)` (plus `-webkit-mask-image`).
- `pointermove` on `.portrait` sets `--mx` / `--my` in px relative to the element. `pointerenter` animates `--r` to 140px; `pointerleave` animates it to 0. `--r` is registered with `@property` so CSS can transition it.
- Touch: the same pointer events. `touch-action: pan-y` on the portrait, so vertical page scroll still works and a horizontal drag moves the circle.
- Click or tap toggles `.is-revealed`, which shows the full colour photo (mask removed).

### 3D project ring (`hero.js`)

- Cards come from the global `PROJECTS` array (`thumb`, `title`). No duplicate data.
- Container `.ring` uses `transform-style: preserve-3d` with perspective on its parent. Card *i* gets `rotateY(i * 360/n deg) translateZ(R)`.
- The ring sits behind the portrait. The sketch image is a cut-out, so cards show around it.
- Rotation angle lives in JS. It auto-rotates slowly (~6°/s). Pointer drag on the ring changes the angle; on release, velocity decays (inertia), then auto-rotate resumes.
- A click on a card (not a drag; movement < 5px) calls the existing `openProject(id, trigger)`.
- Cards are `<button>`s with `aria-label` = project title. The ring is `aria-hidden="false"`, but the Work section stays the primary accessible path.
- Auto-rotate pauses when the hero is off-screen (IntersectionObserver) and when the tab is hidden.

### Scroll / intro animations (`main.js`)

- Intro: hero name letters rise from a clip mask with a stagger; portrait fades and scales in; the badge starts rotating.
- `.reveal` elements fade and rise on enter (ScrollTrigger batch).
- Stats count up once when they enter the viewport.
- Light parallax on the portrait while scrolling the hero.

### Reduced motion and fallbacks

- `prefers-reduced-motion: reduce`: no intro or scroll animations, no auto-rotate, no badge spin. The ring can still be dragged. The reveal mask still follows the pointer, since it only reacts to user input.
- If GSAP fails to load (`typeof gsap === 'undefined'`): add `.no-motion` to `<html>`. CSS then shows all `.reveal` content immediately, and stats show their final values.
- A missing portrait image falls back to the existing placeholder handling.

## Content the user must supply

1. `assets/img/portrait.png`: transparent cut-out, ≥1200px tall.
2. WhatsApp number in international format.
3. 2–4 testimonials: quote, name, role, optional photo.
4. Which institution logos may be shown (SVG preferred).

Until these arrive, the build uses clearly marked placeholders: the current `portofolio.png`, a `#` WhatsApp link with a TODO comment, and a testimonials section hidden behind an HTML comment. Placeholder content never ships as if it were real.

## Testing

Manual checklist in the browser, at desktop width and at 375px:

- Reveal circle follows mouse and finger; click toggles the full photo.
- Ring drags with inertia, auto-rotates, and a card click opens the right modal.
- Theme toggle works and respects the OS preference.
- Modal opens and closes with `Esc` and returns focus.
- Contact form sends through EmailJS, and the no-JS `contact.php` fallback still works.
- `prefers-reduced-motion` emulated in DevTools: nothing auto-animates.
- GSAP blocked in DevTools: all content is visible.
- No horizontal scroll at 375px.
- Lighthouse ≥ 90 on Performance and Accessibility.

`tools/make-sketch.py` has an assert-based self-check: the output has the same size as the input and keeps the alpha channel.

## Out of scope

Cursor-following project preview, language switcher, CMS or build tooling, and new backend endpoints.

## Deploy safety

A push to `main` deploys live via FTP. All work stays on `redesign`. Merge to `main` only with the user's explicit approval.
